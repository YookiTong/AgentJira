# Agent Jira · 项目工作台

[English documentation](README.en.md)

一个在本机运行的 AI 团队项目管理应用。每个项目拥有独立的需求、主管、团队、模块任务和聊天记录。输入目标后，主管先整理需求；用户确认后，主管自行设计团队与实验计划，安排并行工作，在汇合节点检查实际交付物并自动继续。一个模块就是一个可执行任务。

## 中文与英文

右上角可切换「简体中文 / English」，也可直接打开 `/?lang=zh-CN` 或 `/?lang=en`。两种语言使用相同的页面、卡片、二级标签、数据与执行逻辑，包含设置、详情、空状态、错误提示和无障碍标签。

新项目记录创建时的语言，主管的需求、团队命名、计划、审核反馈和最终总结按该语言生成；用户明确指定的交付语言优先。切换界面语言不会翻译或改写已有项目材料、名字、聊天与文件。旧项目未设置语言时使用中文。API 创建可传 `language: "zh-CN" | "en"`，未传时读取 `Accept-Language`。英文 OpenAPI 使用 `/api/openapi.json?lang=en`。

## 启动

需要 Node.js **22.16+**、Git 和已登录的 Codex。Node 22 的内置 SQLite 可能打印 experimental 提示，不影响使用。

```sh
npm ci
npm run build
npm start
```

打开 <http://127.0.0.1:4310>。服务只监听 loopback。浏览器关闭后服务仍可运行，停止终端服务会中断执行并保存记录。

Codex 路径优先级：设置里的路径 → `CODEX_BIN` → PATH → 常见桌面版附带路径。路径设置留空时自动检测；在「设置与模型」中可以检查连接、选择默认模型和调整并发/返工/阶段上限。登录沿用本机 Codex，凭据不经网页保存。若未登录，使用对应可执行文件运行 `codex login`。

可选环境变量：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `HELIU_PORT` | `4310` | 本地服务端口 |
| `HELIU_DATA_DIR` | `.data` | SQLite、附件、产出及工作区目录 |
| `CODEX_BIN` | 自动检测 | Codex 可执行文件路径 |
| `HELIU_URL` | `http://127.0.0.1:4310` | 真机冒烟测试连接地址 |

## 使用

1. 在首页输入目标，可附加文件、选择参考目录，或选择本机 Codex 聊天作为上下文。点击「开始整理需求」，无需选择团队模板。
2. 在「需求」页检查目标、范围、输入、约束、交付物、完成标准和项目类型。可直接编辑或与右侧主管讨论；解决待确认问题后，点击「确认需求并制定计划」。确认前不会启动成员任务。
3. 主管按这个项目的需求组建团队，同时生成实验计划和实际模块。普通项目包含执行与验证方法；研究模块按需补充假设、变量、对照、实验设置和评价指标。
4. 查看模块图、任务看板或角色看板，点击模块打开统一详情：任务说明、方法、输入、验收标准、实际执行记录与产出。验收通过的文件进入「交付物」；未通过的任务最多自动返工两次，上游未通过时下游继续等待。
5. 询问进度不会修改计划。执行中的范围变更会先暂停本项目、修订需求，重新确认后再规划。针对节点发 Prompt 会重新执行该节点，并使下游结果失效、重新验收。历史需求、计划、执行记录和文件继续保留。
6. 可随时暂停和继续。服务重启时，无法确认的运行保留为中断状态，查看记录后继续，避免重复执行。

**项目导航**：左侧是完整项目列表，每个项目显示名称、目标摘要和当前状态；顶部只保留当前项目的「需求、实验计划、模块图、任务看板、角色看板、交付物、项目动态」。各项目分别记住页面、聊天草稿和流程图位置，切换项目或刷新不会串数据。旧标签缓存会保留项目视图和草稿，首页地址始终打开首页。窄屏通过「项目」按钮展开完整列表。

正文使用整页纵向滚动；角色与任务看板可横向滚动。模块图滚轮用于浏览页面，缩放使用画布上的加减按钮或触控板捏合。右侧对话独立滚动，新消息不会把正文拉到页面底部。

**三种任务视图共享数据**：任务看板固定三列「准备进行 → 正在进行 → 已经完成」。待执行、阻塞和中断归第一列并展示原因；执行和验收归第二列；只有通过验收才进入第三列。角色看板每种角色一列，同角色多人共用一列，卡片显示具体负责人，列头可编辑成员职责和配置。

**有名字的团队**：每个项目的主管有独立名字，点击右侧名片即可修改。主管组队时为成员命名，名字和角色分别展示；在角色看板中可以编辑成员名字、职责与模型。右侧「项目协作」提供「对话」与「进展」，分别用于沟通和回看项目更新。需求、方案、结果与历史记录按卡片组织，完整方案和原始日志可展开查看。

**优先级**：统一使用 **0–10 的整数**，数字越大越优先，10 最高；只对依赖已满足的模块生效。待执行模块可以在详情中调整。旧项目的 0–100 数值首次启动时按比例四舍五入换算，同步转换历史计划快照；迁移前的完整项目 JSON 留存在 SQLite 的 `project_migrations` 表中，不改写执行记录、会话与交付文件。

旧版项目保留原任务、会话和完成状态，页面明确标记为旧版，不补造历史需求确认或实验计划。主动修订需求后进入新流程。

首页导入仅读取本机 app-server 可访问的聊天。导入内容保存为项目快照，项目使用新的专属会话。远程或云端聊天不保证在本机历史中可见。

**代码项目**：主管在需求中建议项目类型，用户确认是代码开发后才准备 Git worktree，角色设计不受类型限制。选择已有 Git 仓库时，从当前干净提交创建专用集成分支；未提交的修改不会被自动覆盖。未选择仓库时，会在项目数据目录内新建仓库。普通成员使用独立 worktree，汇合任务使用项目集成 worktree；未合入集成分支的已验收提交会触发额外的集成与检查节点。不会自动向远端推送或发布。产出路径和集成分支可在项目动态中查看。

## 架构

```text
React / React Flow
        │ JSON API + SSE
Fastify ── SQLite 项目快照 / 事件 / 运行记录 / 会话映射
        │
主管结构化决策 ── 确定性调度器 ── 隔离工作区与产出快照
        │                             │
        └────── AgentBackend ──────────┘
                   │
             Codex app-server (stdio JSON-RPC)
```

- 业务数据使用工作台的项目、任务和会话 ID。Codex 的线程 ID、调用方式和协议事件仅存在于 `server/backends/codex.ts` 中。
- `AgentBackend` 定义能力、连接检查、会话创建/恢复、结构化运行、取消、可选历史读取及状态检查。首版只有 Codex 的真实适配器；测试适配器用于验证业务层不绑定供应商。
- 后续 vLLM 适配器需组合推理客户端和工具执行循环，并输出同一事件与结果契约。仅替换推理 API 不等同于具备文件/命令执行能力。
- 主管、成员和验收结果必须符合结构化 schema；调度器检查成员引用、依赖存在性、无环性和运行占用。全服务默认同时最多 3 个成员执行，主管调用按项目串行。
- 新流程分别保存「需求整理／待确认／计划生成／执行交付」阶段和暂停、阻塞等运行状态。需求有独立版本和确认记录，计划快照绑定确认的需求版本；开始、继续、重试和计划导入均不能绕过确认。确认接口对同一版本幂等，过期版本返回冲突。
- 每个项目都有计划版本与执行尝试记录；返工使用新的执行尝试，调整目标使用新任务 ID 并保留已替代节点。历史文件快照保留在数据目录，当前交付列表仅显示已验收的有效结果。
- 当前项目通过 SSE 更新，后台项目列表每 10 秒同步状态。当前项目、页面和聊天草稿仅作为浏览器本地视图状态保存，不控制服务端任务生命周期。
- 单个调用最长 20 分钟；默认最多自动推进 8 个阶段，避免无限扩展。阶段数、并发数和返工次数均可配置。
- 开发模式同源白名单包括 `http://127.0.0.1:5173` 和 `http://localhost:5173`；服务拒绝外部 Host/Origin 和跨站请求。附件和交付物下载只允许读取已登记且仍在项目目录内的真实文件，阻止符号链接逃逸。模型输出 Markdown 不执行 HTML。

## Codex / Agent API

完整接口和请求 schema：<http://127.0.0.1:4310/api/openapi.json>。

| 方法与路径 | 功能 |
| --- | --- |
| `POST /api/projects` | 提交目标，支持 `Idempotency-Key`；`start:false` 可先添加附件 |
| `GET /api/projects/:id` | 获取完整项目、团队、任务、执行与产出记录 |
| `PUT /api/projects/:id/requirements` | `{version, document}`，基于当前版本保存需求修订；首次版本为 `0` |
| `POST /api/projects/:id/requirements/confirm` | `{version}`，确认最新需求版本并自动规划；重复确认幂等 |
| `POST /api/projects/:id/messages` | 给主管发消息；带 `taskId` 为节点 Prompt |
| `POST /api/projects/:id/control` | `start` / `resume` / `pause` |
| `PATCH /api/projects/:id/tasks/:taskId` | 调整待执行节点的负责人、优先级（整数 0–10）、依赖 |
| `PATCH /api/projects/:id/supervisor` | `{name}`，修改本项目主管的名字（1–40 字） |
| `PATCH /api/projects/:id/members/:memberId` | 编辑成员名字、角色、职责、模型 |
| `GET /api/projects/:id/events` | SSE，支持 `Last-Event-ID`；重连先发送最新快照 |
| `GET /api/projects/:id/plan` | 导出计划 JSON |
| `PUT /api/projects/:id/plan` | 暂停后导入计划；已验收节点不可被改写 |
| `POST /api/projects/:id/attachments` | 添加 base64 附件，单文件最多 10 MB |
| `GET /api/projects/:id/artifacts/:artifactId` | 下载产出或参考材料 |

最小创建请求：

```json
{
  "goal": "生成一份本地项目使用说明并验收",
  "language": "zh-CN",
  "start": true
}
```

`start:true` 只启动需求整理。读取项目并检查最新 `requirements` 后，向确认接口提交对应 `version` 才会启动规划和成员执行。创建请求的旧 `template` 字段仍兼容，作为项目类型提示，不再选择固定团队。

需求文档包括 `title`、`projectType`（`development` / `research` / `content`）、`objective`、`scope`、`inputs`、`constraints`、`deliverables`、`acceptance`、`questions`，除 `title`、`projectType`、`objective` 外均为字符串数组。`questions` 必须为空才能确认。

计划使用 `title`、`summary`、`strategy`、`requirementsVersion`、`question`、`members` 和 `tasks`。任务包含 `id`、`title`、`description`、`memberId`、`kind`（`task` 或 `join`）、`dependencies`、`acceptance`、`priority`，并支持 `method`、`inputs`、`expectedOutputs` 数组和可选 `experiment`。实验对象包含 `hypothesis`、`variables`、`controls`、`setup`、`metrics`。导出实际计划可获得可编辑示例；旧计划可省略新增任务字段。导入含未完成旧任务的计划时，工作台分配新 ID，避免覆盖旧执行记录。方案里的模块 ID 对应实际任务，页面可直接定位详情。

## 开发与验证

```sh
# 两个终端分别运行（前端通过代理访问本地 API）
npm run dev
npm run dev:web

# 静态检查、生产构建与核心行为测试
npm run check
npm run build
npm test

# 启动主服务后，使用真实 Codex 自动完成一个极小离线项目
npm run smoke:codex

# 英文真实项目，同样验证并行执行和实际文件交付
HELIU_LANGUAGE=en npm run smoke:codex
```

自动测试覆盖并行与汇合、验收返工、真实文件检查、重复派发防护、多项目并发上限、暂停恢复、服务重启、目标调整、只询问进度、计划导入、代码集成以及接口来源校验；同时覆盖需求版本与确认幂等、确认前执行门槛、多个项目的切换与草稿恢复、三列状态映射、同角色多人合列、独立组队和旧项目兼容，以及优先级边界、一次性数据迁移和主管名字的项目隔离与持久化。另有中英文文案完整性、占位符不改写用户内容、英文项目完整闭环及英文 API 契约测试。测试使用独立临时目录和显式测试后端，不连接模型。

真实冒烟测试需要可用的 Codex 登录，会创建一个真实项目，验证确认前没有成员执行，再自动确认该测试项目的需求。检查两个模块实际并行生成 `introduction.md` 和 `steps.md`，汇合生成 `quickstart.md`，主管验收并完成交付；同时校验运行时间重叠、计划与需求版本绑定和所有文件可下载。中文验证摘要写入 `.cache/codex-smoke-v2.json`，英文写入 `.cache/codex-smoke-en.json`。这会使用当前账户的模型额度。测试超时会暂停该项目并保留现场。

`vLLM` 接入、多人账号与远程部署属于后续扩展。

数据目录 `.data/`、协议检查缓存 `.cache/` 和依赖均已从 Git 排除。备份数据时先暂停项目并停止服务，再复制整个数据目录，以同时保留 SQLite 与工作区文件。
